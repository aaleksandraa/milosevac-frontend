# Architecture audit — Miloševac.com (M0)

Date: 2026-09-01  
Scope: read-only inspection of `milosevac-frontend` (this repo) and gitignored `backend/` checkout of `milosevac-backend`.  
No application code was changed for this document.

## 1. Stack

| Layer | Discovery |
|---|---|
| Frontend | React 18.3.1, Vite 5.4.19, react-router-dom 6.30.1, TanStack Query 5.83.0, Tailwind 3.4.17, TypeScript 5.8.3 |

## 2. Database

| Environment | Engine |
|---|---|
| Production config | `DB_CONNECTION=mysql`, database `milosevac` (`backend/deploy/env/backend.env.example`) |
| Local default | SQLite |
| PHPUnit | SQLite `:memory:` (`backend/phpunit.xml`) |
| Also configured | Laravel `mariadb` and `pgsql` connections exist; unused in production env example |
| PostGIS | **Not available.** Do not migrate the CMS to PostgreSQL. |

**Exact production MySQL/MariaDB version is not pinned in the repository.** Deploy docs require “MySQL/MariaDB”. `backend/deploy/server/inventory.sh` prints `mysql --version` / `mariadb --version` on the server. M1 must not guess; spatial native types stay pending a live `SELECT VERSION()` probe.

## 3. API

Public JSON REST in `backend/routes/api.php`. Controllers return `response()->json(...)`. No Laravel API Resources on existing endpoints. No GraphQL.

| Method | Path |
|---|---|
| GET | `/api/content`, `/api/content/{slug}` |
| GET | `/api/outages` |
| GET | `/api/weather` |
| GET | `/api/fk-posavina`, `/api/fk-posavina/matches/{slug}` |
| GET | `/api/ads` |

Frontend client: `src/lib/backend.ts` (`apiUrl()`). Dev Vite proxy → `VITE_BACKEND_URL`; prod `https://api.milosevac.com`.

Future atlas endpoints should be namespaced `/api/geo/...` and may introduce API Resources without rewriting `/api/content`.

## 4. Content models

Laravel: `Post`, `Category`, `Tag`, `Media`, `SeoMetadata`, `Setting`, `FootballMatch`, `PowerOutageIngestion`, `Place`.

Frontend names the same concepts `Article` / `Category` (`src/data/content.ts`). `ArticlePlace` is `{ slug, name, locative, isPrimary }` for outage/news tagging only.

## 5. Existing `places` (do not reuse as atlas)

Table `places` (migration `2026_08_29_120000_create_places_table.php`):

- `name`, `slug` (globally unique), `locative`, `aliases` JSON, `is_primary`, `sort_order`
- No coordinates, hierarchy, OSM ids, or geometry
- `is_primary` means “this is Miloševac for portal/outage ranking”, not an administrative type
- `PlaceSeeder` mixes settlements (Miloševac, Vranjak, …) with Modriča as a flat sibling
- `PlaceMatcher` substring-matches aliases against Elektro Doboj notice text

**Atlas POIs must not be named `places`.** Use `geo_places` in a later milestone. Optional later link: `geo_settlements.outage_place_id` → `places.id`.

## 6. Routes (frontend convention)

Bosnian path slugs in `src/App.tsx`: `/`, `/omilosevcu`, `/clanak/:slug`, `/kategorija/:slug`, `/fk-posavina`, `/fk-posavina/utakmica/:slug`, `/vrijeme`, `/prekidi-struje`, `/kontakt`, legal pages.

Keep `/omilosevcu` as the editorial about page. Atlas URLs (later): `/mjesta/{jedinica}/{naselje}` — municipality-qualified, never a globally unique settlement slug.

## 7. SEO / sitemap / crawlers

- SPA shell SEO in `index.html`; most pages set `document.title` in `useEffect`
- Crawlers redirected via `public/.htaccess` to Laravel `FrontendRedirectController` + `App\Support\Seo`
- Sitemaps generated by Laravel `SitemapController`; frontend `sitemap.xml` is an index
- Every future public atlas route needs: SPA route, htaccess crawler list, Laravel OG handler, sitemap entry, indexability threshold

## 8. Images, queues, scheduler, tests, deploy

- Images: Intervention Image → WebP; `resolveMediaUrl` on the frontend
- Queues: `jobs` tables + Supervisor example; **no Job classes yet**
- Scheduler: `outages:ingest --retry-pending` hourly 08:00–15:00 Europe/Sarajevo
- Tests: Vitest (frontend); PHPUnit Feature/Unit (backend)
- CI frontend: `.github/workflows/deploy.yml` — lint, test, build, SSH
- Maps: **none installed**

## 9. Reuse vs new

Reuse: `apiUrl()`, React Query hooks, `SiteLayout` / design tokens, Seo/sitemaps/OG pipeline, `media`, queue infrastructure, PHPUnit/Vitest layouts, existing `places` as outage dictionary.

Do not reuse: `places` as national settlements, `is_primary` as geo semantics, `/omilosevcu` as the atlas profile, WeatherService hardcoded coordinates as climate normals.

## 10. Blocking issues (M0)

1. Dual repo: schema lives in milosevac-backend.
2. Production engine version unknown → native `POINT`/`MULTIPOLYGON` pending probe.
3. PHPUnit SQLite cannot run `ST_*`.
4. `places` name collision.
5. Plesk/VPS may lack GDAL for later DEM/ERA5 (offline processing).
